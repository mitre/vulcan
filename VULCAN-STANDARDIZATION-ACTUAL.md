### ✅ Step 6-7: Fix Build Issues - THE CRITICAL LEARNINGS

This is where we discovered what's needed for real-world apps.

#### Issue 1: Missing Build Dependencies
**Problem:** fast_excel gem failed to compile
**Root cause:** Missing zlib1g-dev, git, gnupg packages
**Solution:** Add to config/dockerfile.yml

```yaml
packages:
  build:
    - git       # For gems from git repos
    - gnupg     # For apt-key operations
    - zlib1g-dev # For fast_excel compression
```

#### Issue 2: Corporate CA Certificates
**Problem:** Need custom SSL certificates for corporate environments
**Solution:** Create dockerfile instructions file

**File:** `config/dockerfile-instructions-base.dockerfile`
```dockerfile
# Install custom SSL certificates from certs/ directory
COPY certs/ /usr/local/share/ca-certificates/custom/
RUN cd /usr/local/share/ca-certificates/custom && \
    for cert in ./*.pem ./*.cer; do \
      [ -f "$cert" ] && mv "$cert" "${cert%.*}.crt" || true; \
    done && \
    if ls ./*.crt 2>/dev/null | grep -q .; then \
      apt-get update -qq && \
      apt-get install --no-install-recommends -y ca-certificates && \
      update-ca-certificates && \
      rm -rf /var/lib/apt/lists /var/cache/apt/archives; \
    fi && \
    cd /rails

# Set Node and system to use custom certificates
ENV NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt \
    SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt \
    REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
```

**Add to config/dockerfile.yml:**
```yaml
instructions:
  base: config/dockerfile-instructions-base.dockerfile
```

#### Issue 3: Prometheus Port
**Problem:** Need to expose port 9394 in addition to 3000
**Solution:** Create deploy instructions file

**File:** `config/dockerfile-instructions-deploy.dockerfile`
```dockerfile
# Expose Prometheus metrics port (in addition to default web port)
EXPOSE 9394
```

**Add to config/dockerfile.yml:**
```yaml
instructions:
  deploy: config/dockerfile-instructions-deploy.dockerfile
```

#### Issue 4: Production Seeding
**Problem:** db:prepare tries to seed in production, but seeds.rb rejects it
**Solution:** Use db:migrate instead

**Add to config/dockerfile.yml:**
```yaml
migrate: "./bin/rails db:migrate"
```

## Reusable Pattern for Other Projects (Heimdall2, etc.)

### Step-by-Step Recipe

1. **Add gem:**
   ```bash
   # Gemfile
   gem 'dockerfile-rails', group: :development
   bundle install
   ```

2. **Initial generation:**
   ```bash
   rails generate dockerfile --postgresql --jemalloc --compose
   ```

3. **Identify app-specific needs:**
   - Run `docker build` to find missing dependencies
   - Check what gems need native extensions
   - Note any corporate cert requirements

4. **Create instruction files:**
   - `config/dockerfile-instructions-base.dockerfile` - CA certs, base setup
   - `config/dockerfile-instructions-deploy.dockerfile` - Extra ports, final config

5. **Update config/dockerfile.yml:**
   ```yaml
   packages:
     build:
       - [your app's build dependencies]
   instructions:
     base: config/dockerfile-instructions-base.dockerfile
     deploy: config/dockerfile-instructions-deploy.dockerfile
   migrate: "./bin/rails db:migrate"  # If seeds shouldn't run in prod
   ```

6. **Test:**
   ```bash
   docker build -t app:test .
   docker run -d -p 3000:3000 app:test
   curl http://localhost:3000/up
   ```

7. **Iterate:** If build fails, add missing packages to config/dockerfile.yml, regenerate

## Key Learnings

### What Works
1. **dockerfile-rails is robust** - Handles Rails apps well
2. **Customization via config files** - Not manual Dockerfile edits
3. **Single source of truth** - config/dockerfile.yml + instruction files
4. **Reproducible** - Anyone can regenerate same Dockerfile

### What to Watch For
1. **Native extension gems** - May need specific build packages (check gem's C dependencies)
2. **Corporate environments** - Need CA cert handling
3. **Custom ports** - Use deploy instructions
4. **Production vs dev** - Consider migrate vs prepare

### Common Build Dependencies
- `git` - Almost always needed
- `gnupg` - For apt operations
- `zlib1g-dev` - Compression (many gems need this)
- `libpq-dev` - Already included by --postgresql
- `build-essential` - Already included by dockerfile-rails

3. **Documented** - Config file explains all choices

5. **No drift** - Can't have two different custom Dockerfiles
